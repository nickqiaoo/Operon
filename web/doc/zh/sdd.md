# 规格驱动开发

## 这是什么

规格驱动开发（SDD）把讨论变成可评审的**变更包**：规格、需要时的计划，以及实现之后的验收报告。先由你批准设计，Agent 再开始编码；完成后由你审阅并标记完成。

SDD 按每次变更选择使用。在工作区聊天或频道里，让 Agent 把谈妥的设计建成规格任务即可，没有频道级开关。

## 为什么用它

- 实现之前先写下并评审设计。
- 规格与计划和代码一起保存在 git 中。
- 服务端关卡保证设计批准后才能实现、你审阅后才能完成。
- 完成的变更可以沉淀回项目的活规格。

## 如何开启

讨论变更、确认待定问题，让 Agent 创建规格任务。它会出现在项目看板，带独立分支与工作区。主笔写好规格和计划，然后交还给你。

> SDD 需要 git 仓库。先在任务详情阅读文档，再用 **Dispatch** 签收设计、启动工作。

## 变更包

两级任务都会出现在看板上：

- **父任务** — 保存规格与计划。规格包含验收场景；验收文档是实现结束后才由验收者撰写的报告。
- **子任务** — 已批准计划的执行切片，各有分支和负责的验收标准，通过规格与计划继承上下文。

很小的变更可以省略计划与子任务，作为一个任务运行。

## 流程

1. **讨论** — 在工作区聊天或频道里对齐需求。
2. **创建** — Agent 创建规格父任务，带独立的变更工作区。
3. **规格与计划** — 主笔记录设计、解决待澄清标记、写出执行计划，不提前撰写验收报告。
4. **派发** — 你按 **Dispatch** 批准设计，选择执行者并启动。计划条目变成子任务。
5. **执行** — 计划按顺序分批执行，独立条目可以并行。已完成的子任务先合入变更分支，再启动依赖它的工作。明确的协调组可使用团队 inbox。
6. **验证与审阅** — 进入待审阅时，选择独立验收者，或明确选择不经独立验证就签收。验收者撰写报告，由你决定是否就绪。
7. **完成与沉淀** — 标记 Done 会批准验收、在存在规格增量时应用它，再合入项目默认分支。冲突会阻止完成；未运行验收者就签收会被明确记录。

## 审批关卡

**Dispatch** 会一并批准规格与计划、准备任务。未解决的澄清标记会阻止规格批准。Agent 完成后交还人工审阅，不会把自己的任务标成 Done。

已批准文档会检查后续改动。内容变动会回到草稿，需要重新签收；父任务完成前，子任务必须先完成。

## 在任务详情页

**spec / plan / acceptance** 面板显示文档及状态。Dispatch 是设计批准入口。待审阅时可运行验收者并查看报告；用 **Preview sediment** 和 **Apply sediment** 检查、应用活规格更新。存在冲突时要先解决才能应用。
