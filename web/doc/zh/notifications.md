# 通知

Operon 在两个地方告诉你哪些工作完成了、哪些卡住了：App 内的 **Inbox**，以及来自 macOS 的**系统通知**。

## Inbox

Agent 在后台运行，跨越多个 workspace，往往发生在你没有看着的标签页里。Inbox 就是那个把"你不在时发生了什么"收拢起来的入口。

从顶栏的**铃铛**打开它。角标统计的是**在等你处理**的条目；已完成的工作会列出来，但不会把角标点红。

### 哪些东西会进来

| 类型 | 触发时机 |
| --- | --- |
| **回复完成** | 某个 workspace 对话里 Agent 结束了一轮回复 |
| **待验收** | 派发出去的任务进入 `in_review`，等你签收 |
| **已完成** | 任务完成 |
| **失败** | 任务失败或被取消 |

用 **Needs you** 过滤出只卡在你这里的条目，用 **Done** 查看完成通知。

### 每个来源只占一行

Inbox 是一份状态列表，不是事件流水。每个对话或任务只占据一行，反映它当前的状态。如果同一个对话再次完成，更新的是它已有的那一行并重新标记为未读，而不是再堆一条新记录——所以长会话不会把面板刷屏。

点击一行会把它标记为已读并跳转到来源：对话会在它所属的 workspace 中打开，任务会打开详情视图。**Mark all read** 可一次性清空角标。

当没有任何待办时，面板会提示你已经全部处理完了。

### 为什么放在服务端

"完成"这个事实记录在服务端，而不是浏览器标签页里。没有在流式输出的对话标签页会被卸载，后台任务完成时 App 甚至可能根本没开着——所以这个事件必须在没有活动标签页接收的情况下依然留存。这也是为什么 Inbox 在桌面端、[移动端](mobile)和[远程网页访问](remote-access)之间是一致的：它们读的是同一份记录。

## 系统通知

Inbox 面向"你回来之后"，系统通知面向"你正在别的应用里"。

进入 **Settings > Notifications**：

- **窗口未聚焦时显示系统通知** — 总开关。当你正在看着 Operon 时不会发送任何通知。
- **回复完成时通知** — Agent 结束了它的回复。
- **需要审批时通知** — 某个工具正在等待你的许可。

审批请求是最值得保持开启的一类：需要许可的 Agent 在你回答之前会一直停住，如果没有通知，它可能会干等很久。

具体如何展示由 macOS 决定。如果什么都没出现，检查一下 **系统设置 > 通知** 里 Operon 的条目。
