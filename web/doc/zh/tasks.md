# 任务

## 这是什么

任务（Tasks）是 Operon 自带的项目级任务追踪器。要做的事不用再埋在聊天记录里——每个项目都有一块真正的看板，人和 Agent 在上面建任务、派活、盯到完成。Agent 可以领一个任务，在单独的 git 分支上做，边做边回报进度，整个过程都在 Operon 里。

任务与频道并列。在项目的频道区域，可从侧栏在频道 **Chat** 视图和 **Tasks** 视图之间切换。

## 视图

同一份任务列表可以用三种方式展示：

- **List（列表）** — 紧凑的分组列表。可按状态、优先级、负责人或团队分组。
- **Board（看板）** — 每个状态一列的看板，列间支持拖拽。
- **Teams（团队）** — 按负责的团队（inbox 协作组）组织任务。

顶部的筛选器可按状态、负责人、优先级或团队收窄，**显示已归档** 开关可把已完成 / 已取消的工作重新调出。

## 任务构成

每个任务包含：

- **标题与描述** — 要做什么。
- **状态** — `todo` → `in_progress` → `in_review` → `done`（或者 `cancelled`）。只能按顺序走，中间几步跳不过去。
- **优先级** — 无、低、中、高、紧急。按优先级排的时候紧急排最前。
- **负责人** — 由哪个 Agent 来做。
- **标签与团队** — 把相关的任务归到一起，也决定协作时找谁。
- **分支** — 派活的时候会开一个独立的 worktree，任务跑在自己的 git 分支上，几件事同时做也不会打架。

## 使用任务

### 创建

点击 **New** 打开任务对话框，填写标题、可选描述、优先级和负责人后保存。Agent 在决定把工作拆成多步时也会自行创建任务。

### 分派给 Agent

打开一个任务并**分派**给某个 Agent。Operon 会为该任务开一个专属的 Git worktree，把任务作为工作上下文交给 Agent，并把状态翻到 `in_progress`。你可以实时观看执行流。

### 评论与唤醒 Agent

任务详情页有评论框。在已分派的任务上留言会**唤醒该任务的负责 Agent**——用它来给反馈、回答疑问或推进工作，无需新开一次对话。所有评论、状态变化、分派与指派事件都会记录在任务的 **Activity（活动）** 时间线里。

### 打开工作区

你可以从任务直接跳进 Agent 正在工作的工作区 / worktree，查看文件或手动接管。

## 实时更新

任务变化通过 Server-Sent Events 流式推送。当 Agent 更新状态、留下评论，或另一个窗口编辑了任务时，看板会即时更新，无需刷新。

## 规格驱动开发

**规格驱动开发（SDD）** 是一套可选的流程，真正干活的那一层就是任务。从开了 SDD 的频道提上来的任务，详情页会多出一块 **规格 / 计划 / 验收** 面板，中间几步要人点头才能往下走。完整流程见 [规格驱动开发](sdd)。

## 与其他界面的区别

- **任务 vs 频道聊天** — 频道是一直在聊的地方；任务是聊出结果之后，落下来能一直追的那件事。
