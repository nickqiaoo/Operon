# 环境与日志

出问题时最需要关注的三项设置：Agent 运行在什么环境里、它们的 CLI 在哪里被找到、以及日志记了什么。

## 环境变量

**Settings > Env** 为 Operon 的服务进程设置环境变量。所有 AI adapter——Claude Code、Codex、OpenCode 等等——都会继承它们，因此这里是配置环境级设置的唯一入口：

- 代理设置（`HTTPS_PROXY`、`NO_PROXY`）
- 某个 provider 的自定义 API 地址
- TLS 相关的覆盖设置
- 任何 CLI 指望从环境里读到的东西

单个 Agent 可以为自己覆盖这些变量——见 [Agent 编辑器](channels)里的环境变量字段。

## CLI 路径

Operon 运行的是真实的 CLI 二进制。它通过询问你的**登录 shell** 来找到它们，这也是为什么在终端里能用的 CLI 在这里通常也直接能用——哪怕它是由某个从不改动系统 `PATH` 的版本管理器安装的。

每个 provider 页签都会显示解析结果：

- **Available** / **Not found** — 二进制是否真的存在。
- **Resolution** — 实际使用的路径。

保持自定义路径为空即维持自动发现。只有在自动发现选错了二进制、或你需要某个特定版本时才去设置它。如果你填过的路径后来失效了，Operon 会明说，然后退回自动找到的那个，而不是悄悄地不工作。

## 调试日志

**Settings > Logs** 开启文件日志用于排查问题。日志上限 10 MB，会自动轮转。

在同一页签里，你可以内联 **View Log** 查看、在复现问题时 **Refresh** 刷新，或者 **Reveal in Finder** 把文件取出来附到问题报告里。

日常使用保持关闭；有需要复现的问题时再打开。

> 日志页签仅限桌面端——在[远程网页访问](remote-access)中它会被隐藏，因为日志文件在机器上，而不在浏览器里。
