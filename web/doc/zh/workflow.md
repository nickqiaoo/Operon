# 画布工作流

## 这是什么

画布工作流是一个可视化的编辑器：在画布上把节点连起来，就搭出了一条多步的 AI 流水线。你可以把几个模型串在一起，让前一个的输出喂给后一个，然后一键跑完整条线。

## 工作原理

一条工作流本质上是一张 **DAG（有向无环图）**。跑起来的时候，引擎会看清节点之间谁依赖谁，然后按最省时间的顺序执行——彼此无关的节点同时跑，下游节点一旦拿到需要的输入就立刻开始。

这里的关键是**谁先完成就先推进谁**：引擎不会等一批并行节点全部跑完才继续，而是每收到一个完成的节点，就马上启动因它而解锁的下游节点。这样才是真的并行，而不是被最慢的那个节点拖着。

## 节点类型

### AI 节点

干活的节点：把提示词发给模型，拿回结果。可以设置：

- **Agent 与模型** — 用哪个 Agent、哪个模型。
- **模式** — 运行模式（每个 Agent 不一样）。
- **提示词** — 一段模板，写法见下面的[变量](#变量)。

### AI 会话节点

接着上一个 AI 节点继续聊。它不开新对话，而是沿用父节点的会话，所以工作流里也能有真正的多轮对话。在 AI 节点上右键，选 "Continue Session" 就能建一个。

一个 AI 节点最多带一个会话子节点。

### Shell 节点

在工作区里跑一条 shell 命令，stdout 就是它的输出。跑测试、lint、构建、`git` 这类"确定、免费"的事都交给它。默认非零退出码算失败；关掉这个开关就会继续往下走，并把 stderr 附在输出后面。

### 模板节点

不调模型，只用上游变量渲染一段文本。没有上游时它就是一个常量，想用固定提示词或配置开头就用它。适合拼提示词、格式化通知，或者把不同分支的结果合起来（`{{ fixed or original }}`）。

### 代码节点

对上游变量（`inputs`）跑一段 JavaScript 函数体，返回值就是输出；返回对象或数组时会变成 JSON，下游能当数据读。它没有 `require`、文件系统和网络——这些交给 Shell 或 AI 节点。

### HTTP 节点

调用 API 或 webhook，输出响应体。方法、URL、headers、body、鉴权全部是模板，密钥写成 `{{ env.GITHUB_TOKEN }}`。JSON 响应会变成下游可读的数据。非 2xx 默认算失败。

### 结束节点（End）

用 key / 模板声明整条工作流的输出。有它时，运行结果就是这组值（父工作流拿到的就是它）；没有时退回"叶子节点即输出"。

### 迭代分组（Iteration）

一个可以把节点拖进去的分组。**Items** 模板渲染成 JSON 数组（或每行一项），对每一项跑一遍分组内的节点，按设定的并发数并行。组内可以用 `{{ item }}`、`{{ index }}`，组外的变量也都能读。每一轮的 **Result** 模板收集成一个 JSON 数组作为分组的输出。

### 循环分组（Loop）

反复执行组内节点，直到 **Exit when** 表达式为真或到达 **Max rounds** 上限。**循环变量**在轮次之间传值：每个有初始模板和每轮结束后求值的 `next` 模板，组内用 `{{ loop.<name> }}` 读取。输出会附带 `iterations` 和 `exhausted` 两个字段。

### 子工作流节点

调用另一条工作流。给它一组变量（名字 → 模板），在子工作流里它们就是普通变量，一行叫 `file` 的在那边就是 `{{ file }}`。有调用方之后，子工作流的变量选择器会在"From calling workflows"分组里列出这些名字。子工作流的结束节点输出就是这个节点的输出。保存时会拒绝循环引用，被其他工作流调用的工作流不能删除。

### 审批节点

暂停运行，往收件箱（和手机）发一条审批请求。在结果面板里点 Approve 继续，Reject 则该节点失败、后续全部跳过。可选超时。等待期间重启 App 会丢掉这次运行。

### 条件节点（If/Else）

每个 case 逐行搭：变量、操作符（为真、等于、包含、大于、正则匹配……）、值，多行之间用 and / or；行表达不了的可以切到"手写表达式"。按顺序判断各个 case，走第一个为真的分支；都不满足就走 `else`。画布上每个 case 各有一个输出端口。没走到的分支上的节点会标成 **skipped**，前驱全被跳过的节点也会被跳过。合流节点只要有一条分支到达就会执行。

## 结构化输出

AI 节点可以配一个 JSON Schema。配了之后回复必须是符合 schema 的 JSON，不合法时会在同一个会话里追加纠错轮（默认 2 次）。下游直接读字段：`{{ review.passed }}`。

## 触发方式

- **运行按钮** — 手动。
- **定时** — 建一个 cron 任务来跑这条工作流。
- **另一条工作流** — 子工作流节点带着调用方给的变量来跑这条工作流。

## 变量

每个节点的输出，对它之后运行的所有节点都可见，按节点名引用：`{{ summary }}`。不限于直接连线的节点——连线决定顺序，名字决定访问。

基本不用手打：每个模板框右上角有 `{x}` 按钮（或者直接输 `{{`），会列出这个节点能引用的变量；工作流跑过一次之后还会展开每个 JSON 输出里的字段，点一下就插入 `{{ review.passed }}`。引用了上游没有的名字会在框下面提示；模板有语法错误时保存会被拒绝，并指出是哪个节点的哪个字段。

- 输出是 JSON 对象或数组时会变成数据：`{{ review.passed }}`、`{{ files | length }}`。
- 被跳过的节点是 `undefined`，所以 `{{ a or b }}` 能取到实际跑了的那条分支。
- `{{ env.MY_TOKEN }}` 读取 Settings 里配置的环境变量，密钥不用写进工作流。
- 过滤器：`| tojson` 序列化成 JSON，`| lines` 把文本按行切成非空数组。
- 条件节点里的表达式用同一套语法，不带花括号：`review.passed and "FAIL" not in tests`。

## 失败

一个节点失败只会拦住它自己的下游：不相关的分支照常跑完，等所有能跑的都结束后整个运行才标成 error。确定性节点有超时（Shell 默认 30 秒、代码默认 10 秒），输出上限 256KB。

## 怎么用

1. **新建** — 在侧边栏点 "New Workflow"。
2. **加节点** — 用节点面板，或者在画布上右键。
3. **连线** — 从一个节点的输出端口拖到另一个节点的输入端口。
4. **配置** — 点开节点，改它的 Agent、模型和提示词。
5. **运行** — 点运行按钮。画布上每个节点的状态会实时变化。
6. **盯进度** — 点正在跑的 AI 节点可以看它实时的对话，最终结果在结果面板里看。

边改边存，不用手动保存。每条工作流的历次运行记录也都留着。
